# data-to-value

从实际数据和项目资料出发，提出、审查并落实有价值的想法，形成有证据的学术文稿或企业应用方案。

这是一个 Agent Skill（技能包），遵循 `SKILL.md` + `references/` + `scripts/` 的通用目录约定。学术版与企业版共用同一套流程，但价值判断、评分标准和最终交付不同。

## 它解决什么问题

大多数"数据驱动"的失败不是算法不够强，而是链条断了：从数据跳到结论，中间的观察能力、领域问题、可证伪假设、最简单基线都没有交代。这个技能把整条链固定下来并可追溯：

**实际数据 → 可回答的问题 → 学术或业务价值 → 可证伪的想法 → 低成本验证 → 工程实现 → 有证据的表达。**

## 核心特征

- **启动先问版本。** 每个新任务首次启动时先询问学术版还是企业版，不根据"论文""收益"等措辞自行判定，未回复不等于默认选择。
- **偏好先于候选。** 生成候选前先展示偏好设置页，由使用者调整维度权重或明确接受初始配置；权重只影响搜索侧重与排序，不改变事实、评分锚点或证据要求。
- **未知不填分。** 评分使用有锚点的 1–5 分，未知项必须留空并附补证据路径，不用 0 分、默认 3 分或推测值填充；存在未知维度时不输出完整综合分。
- **成熟度与实际价值分开。** 每个候选标注"机会假设 / 可验证方案 / 已获支持方案"；有潜力不等于已验证，能实现不等于能产生价值。
- **最高分不是决定。** 界面预选、浏览图表、未回复都不算选择；主线由使用者明确选定。

## 两版差异

| 项目 | 学术版 | 企业版 |
|---|---|---|
| 核心目标 | 发现值得研究的问题，形成有证据的贡献 | 发掘数据的新用途，改善业务动作或形成服务 |
| 评分维度 | 创新度、研究意义、数据适配、实施可行性、验证设计 | 潜在净价值、见效时间、执行成本、落地条件、效果可测量性 |
| 验证重点 | 假设、对照、独立性、不确定性及贡献边界 | 行动可行性、增量效果、实际成本与采用条件 |
| 后续交付 | 研究设计、实验、论文与审稿修订 | 最小试点、效果评估、工程交接与维护 |

## 完整流程

一次性准备：导入完整技能包 → 初始化必要依赖 → 验收运行能力 → 保存环境配置。已有环境直接复用，缺失依赖安装到专用环境。实际完成检查后才标记就绪，以后正常调用不重复安装。

日常使用：

| 阶段 | 做什么 | 主要输出 |
|---|---|---|
| 1 | 提供资料与选择版本 | 已确认版本 |
| 2 | 明确本轮任务与交付目标 | 本轮范围 |
| 3 | 展示偏好设置页 | 已确认权重与独立约束 |
| 4 | 审核数据（对照说明与实物） | 可用证据、冲突、未知及用途边界 |
| 5 | 生成候选想法 | 实质不同的候选卡 |
| 6 | 查新与现状比较 | 新增价值、合理替代与贡献边界 |
| 7 | 审查并精选 | 默认精选三个候选，不足三个如实展示 |
| 8 | 评分与交互展示 | 可调权重的方案比较 |
| 9 | 用户选择方案 | 明确的主线选择 |
| 10 | 最小验证 | 继续、修正、收缩或停止的判断 |
| 11 | 实施与写作 | 有证据支撑的成果或交付 |
| 12 | 验收与留档 | 可追溯成果及续作记录 |

阶段按需使用，不要求依次全部执行。用户只要其中一环时，不强制重做整套项目。

### 四条关键约束

1. 版本和最终方案由用户选择，不把预选、最高分或未回复当作确认。
2. 权重表达偏好，不能改变事实、补造未知分数或抵消硬伤。
3. 数据关键冲突先处理，暂停依赖它的判断；其他不受影响的工作可以继续。
4. 按请求推进到所需阶段：只要想法就不自动开展实验；更换已确认主线或扩大投入时，先讨论。

## 安装

### 作为 Agent Skill

把本目录放到宿主的技能根目录下，确保 `SKILL.md` 位于技能目录第一层：

```text
<技能根>/data-to-value/SKILL.md
```

常见技能根：`~/.dsh/skills`、`~/.claude/skills`、`~/.agents/skills`、项目内的 `.agents/skills`。

也可以直接从本仓库安装（需要 SkillHub 或兼容的 ClawHub CLI）：

```bash
npx clawhub --dir ~/.dsh/skills install <命名空间>--data-to-value
```

### 依赖

| 能力 | 依赖 |
|---|---|
| 版本选择、偏好确认、评分解释 | 无需表格库 |
| 生成偏好页与评分页 | Python 3.10+ 标准库，无需 pandas / openpyxl / npm |
| CSV / TSV / JSON 基础审核 | Python 标准库即可 |
| 常用 Excel 读取与表格分析 | `requirements-tabular.txt`（pandas、openpyxl） |

初始化（一次性，仅缺依赖时安装到专用环境）：

```bash
python scripts/setup_environment.py --profile tabular          # 只检查
python scripts/setup_environment.py --profile tabular --install # 缺依赖时安装
```

命令中的相对路径以技能目录为基准；工作目录不是技能目录时改用绝对路径。默认状态目录位于用户目录 `.cache/data-to-value`，**该目录不可写时必须用 `--state-dir` 指向可写目录**，否则初始化会以权限错误退出。

## 网页展示说明

偏好页与评分页是自包含的离线 HTML，不需要联网或额外依赖。要让使用者真正看到页面，**HTML 须生成在会话工作区内，并用平台的文件交付工具声明为交付物**；生成到工作区外只保证文件存在，不保证用户能看到入口。

在网页宿主或沙箱 iframe 预览中，页面没有同源权限：脚本可以运行（滑块、评分矩阵、图表都可用），但剪贴板接口不保证可用，页面也访问不到本机回环地址。因此这类环境应以**对话或原生输入工具**收取偏好与方案选择，页面仅用于查看和调权；页面上的"复制"失败时会退化为选中只读文本供手动复制。

## 已验证 / 未验证

已在 Python 3.10.11 + pandas 2.3.3 + openpyxl 3.1.5 上验证：

- 环境探测（core / tabular）、两版偏好页生成、评分报告生成均正常退出
- 本机回环偏好确认全流程（含错误路径拒绝、跨源拒绝、确认后落盘、回执传入比较页）
- 输入校验：分数越界、`null` 与"未知"错配、重复 id、维度不一致、负数权重等均被拒绝
- 报告输出对 `<` 做转义，无脚本注入

**未验证：浏览器内实际渲染。** 滑块拖动、字体、剪贴板兜底等显示细节尚未在目标宿主实测，请按 `references/runtime.md` 的"页面能力按宿主分别验证"表自行确认一次。
