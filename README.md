# data-to-value

当前为持续调试阶段：直接更新 main 与原有下载包，暂不递增发布版本。`v0.1.0` 仅作为固定下载入口；实际内容以下载时的 main 提交及发布页所列提交为准。

从实际数据和项目资料出发，提出、审查并落实有价值的想法，形成有证据的学术文稿或企业应用方案。

这是一个 Agent Skill（技能包），遵循 `SKILL.md` + `references/` + `scripts/` 的通用目录约定。学术版与企业版共用同一套流程，但价值判断、评分标准和最终交付不同。

## 它解决什么问题

大多数"数据驱动"的失败不是算法不够强，而是链条断了：从数据跳到结论，中间的观察能力、领域问题、可证伪假设、最简单基线都没有交代。这个技能把整条链固定下来并可追溯：

**实际数据 → 可回答的问题 → 学术或业务价值 → 可证伪的想法 → 低成本验证 → 工程实现 → 有证据的表达。**

## 核心特征

- **启动先问版本。** 每个新任务首次启动时先询问学术版还是企业版，不根据"论文""收益"等措辞自行判定，未回复不等于默认选择。
- **偏好先于候选。** 生成候选前先展示偏好设置页，由使用者调整维度权重或明确接受初始配置；权重只影响搜索侧重与排序，不改变事实、评分锚点或证据要求。
- **未知不填分。** 评分使用有锚点的 1–5 分，未知项必须留空并附补证据路径，不用 0 分、默认 3 分或推测值填充；存在未知维度时不输出完整综合分。
- **成熟度与实际价值分开。** 每个候选标注"机会假设 / 可验证方案 / 已获支持方案"；有潜力不等于已验证，能实现不等于能产生价值。
- **最高分不是决定。** 界面预选、浏览图表、未回复都不算选择；主线由使用者明确选定。

## 两版差异

| 项目 | 学术版 | 企业版 |
|---|---|---|
| 核心目标 | 发现值得研究的问题，形成有证据的贡献 | 发掘数据的新用途，改善业务动作或形成服务 |
| 评分维度 | 创新度、研究意义、数据适配、实施可行性、验证设计 | 潜在净价值、见效时间、执行成本、落地条件、效果可测量性 |
| 验证重点 | 假设、对照、独立性、不确定性及贡献边界 | 行动可行性、增量效果、实际成本与采用条件 |
| 后续交付 | 研究设计、实验、论文与审稿修订 | 最小试点、效果评估、工程交接与维护 |

## 完整流程

一次性准备：导入完整技能包 → 初始化必要依赖 → 验收运行能力 → 保存环境配置。已有环境直接复用，缺失依赖安装到专用环境。实际完成检查后才标记就绪，以后正常调用不重复安装。

日常使用：

| 阶段 | 做什么 | 主要输出 |
|---|---|---|
| 1 | 提供资料与选择版本 | 已确认版本 |
| 2 | 明确本轮任务与交付目标 | 本轮范围 |
| 3 | 展示偏好设置页 | 已确认权重与独立约束 |
| 4 | 审核数据（对照说明与实物） | 可用证据、冲突、未知及用途边界 |
| 5 | 生成候选想法 | 实质不同的候选卡 |
| 6 | 查新与现状比较 | 新增价值、合理替代与贡献边界 |
| 7 | 审查并精选 | 默认精选三个候选，不足三个如实展示 |
| 8 | 评分与交互展示 | 可调权重的方案比较 |
| 9 | 用户选择方案 | 明确的主线选择 |
| 10 | 最小验证 | 继续、修正、收缩或停止的判断 |
| 11 | 实施与写作 | 有证据支撑的成果或交付 |
| 12 | 验收与留档 | 可追溯成果及续作记录 |

阶段按需使用，不要求依次全部执行。用户只要其中一环时，不强制重做整套项目。

### 四条关键约束

1. 版本和最终方案由用户选择，不把预选、最高分或未回复当作确认。
2. 权重表达偏好，不能改变事实、补造未知分数或抵消硬伤。
3. 数据关键冲突先处理，暂停依赖它的判断；其他不受影响的工作可以继续。
4. 按请求推进到所需阶段：只要想法就不自动开展实验；更换已确认主线或扩大投入时，先讨论。

## 安装

### 作为 Agent Skill

把本目录放到宿主的技能根目录下，确保 `SKILL.md` 位于技能目录第一层：

```text
<技能根>/data-to-value/SKILL.md
```

常见技能根：`~/.dsh/skills`、`~/.claude/skills`、`~/.agents/skills`、项目内的 `.agents/skills`。

仓库当前为私有。下载Release附件或克隆均需已获授权的GitHub账号；不要把访问令牌粘贴到聊天。上传ZIP到技能导入入口，或使用已认证的Git克隆后放入宿主要求的技能目录。本项目尚未声明在SkillHub/ClawHub注册，不提供占位安装命令。

### 一次安装，后续复用

```text
python scripts/setup_environment.py --profile common --install
```

默认准备常用数据配置并逐项验证依赖和合成文件读取。命令由安装助手执行；不在每次上传数据时重复安装。现有环境通过检查就复用，缺少依赖才安装到专用虚拟环境。详细步骤见 [INSTALL.md](INSTALL.md)。导入ZIP是否自动触发初始化由宿主决定；本项目没有假定所有平台都提供安装钩子。

| 配置 | 用途 |
|---|---|
| core | 标准库、交互页面、CSV/JSON/文本/SQLite/ZIP清单 |
| tabular | core加pandas、NumPy、openpyxl |
| common（默认） | 常用Excel、列式数据、文档和结构化文本读取 |
| ocr（选配） | common加图片/扫描PDF识别；需额外准备Tesseract和目标语言数据 |

支持格式与边界见 [数据读取清单](references/data-formats.md)，按平台和格式记录的实测程度见 [兼容性矩阵](references/compatibility.md)。不宣称所有平台、任意数据或所有文件变体均可直接运行。

### 统一读取

```text
<已验收的Python> scripts/read_data.py --input <文件> --output <工作区>/读取结果.json
```

解释器取自 `runtime-common.json` 等配置回执。读取器不安装依赖、不修改源数据；记录抽样、表/页位置、失败原因。解析成功仍需对照数据说明审核，不能当作真实数据认证。

## 网页展示

两版交互页面使用Python标准库生成离线HTML。优先使用宿主交付/预览工具；本地桌面可请求浏览器打开。沙箱iframe可能限制JavaScript、剪贴板或回传，须实测；不支持时通过原生输入或对话确认，不把生成文件等同于页面已展示。

## 检查与测试

```text
python -m unittest discover -s tests -v
```

使用common配置解释器。测试覆盖格式读取、原文件不变、中文路径/控制台、依赖约束、部分读取与错误状态。提供Windows、Linux、macOS与Python 3.10/3.14的GitHub Actions矩阵模板（tests/compatibility-workflow.yml）；当前未启用，不能视为云端测试通过；不替代豆包等客户端账号内验收。

主要文件：`SKILL.md`为入口，`references/`包含按需细则；`scripts/setup_environment.py`负责安装验收，`read_data.py`负责统一读取，`configure_preferences.py`和`render_candidate_scores.py`负责交互页。`requirements-*.txt`声明不同配置的依赖，`tests/`提供回归测试。
