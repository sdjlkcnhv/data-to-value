## 可直接用于详情页的正文

### 用已有数据，找到值得做的方向。

**data-to-value｜根据数据集寻找论文选题，根据业务记录寻找改进机会。**

数据已经在手，值得做的方向还不清楚。你可能下载了一份研究数据集，却迟迟定不下题目；也可能积累了订单、日志和售后记录，却一直停留在报表。

data-to-value 帮你从这些材料出发，找到有依据、能比较、值得验证的下一步。你不必先想出一个好点子，也不必一开始就决定用什么模型。

### 一个入口，两种价值方向

**学术版 · 找到值得研究的问题**

从数据能观察到的现象出发，连接研究问题与已有工作。比较创新度、研究意义、数据适配、实施可行性和验证设计，交付有证据边界的候选选题与最小实验。

**企业版 · 找到值得验证的机会**

从尚未充分利用的数据出发，寻找能够改变业务动作的用途。比较潜在净价值、见效时间、执行成本、落地条件与效果可测量性，交付可讨论的业务机会与最小试点。

### 先看清，再投入

每个候选方案都会说明这些内容：

| 你要判断什么 | 每个方向提供什么 |
|---|---|
| 为什么是这个想法 | 对应的数据字段、已核验事实与尚未确定的假设 |
| 值不值得推进 | 学术新增量或具体业务动作，以及比较依据 |
| 从哪里开始 | 最简单可行基线、最便宜的验证与停止条件 |
| 需要付出什么 | 时间、成本、资源依赖与主要风险；缺少依据则留待核实 |

默认精选三个实质不同的方向，数据不足时如实少给。未知项留空，硬伤不靠总分掩盖。评分帮助你看清取舍，最后由你决定。

### 从你的优先级开始

**① 选版本＋调权重 → ② 审核数据 → ③ 生成并比较候选 → ④ 你选方案，再按需验证落实。**

在同一个启动页选择学术版或企业版，调整各项权重。可从均衡、探索创新、优先可行，或尽快验证、控制投入等配置起步，再自由微调。权重影响寻找和比较方案的侧重点，不改变事实和证据要求。

本机支持任务连接时，点击确认即可把设置交回助手。其他环境可以通过原生表单或一次对话完成同样的选择，无需为了使用技能维护一个网站。

### 不妨先看一次交付

技能包内含两份合成数据、数据说明，以及学术/企业两版离线交互演示。从重复实体、缺失记录，到事后字段与提前预测的区别，你能看到技能如何发现限制，再提出候选。

这些是工作方式的演示，不是论文发表或企业收益案例。

### 用这句话，开始你的第一个项目

> 使用 data-to-value。我有这些数据，但还没有明确想法。第一步让我同时选择学术版或企业版并确认权重，然后审核数据，提出候选供我比较。本轮先做到我选择方案。

### 使用前，只需了解这些

导入完整技能包，在支持Python执行的宿主中完成一次初始化与验收，后续复用。CSV、Excel、JSON、Parquet、文本PDF和Word等按支持清单读取；扫描件需选配OCR。导入ZIP不代表所有宿主都会自动安装依赖。

离线页面不需要付费托管，技能也不要求独立模型API Key；宿主服务、实验资源费用另计。页面展示与自动回传取决于宿主能力，普通聊天入口不保证完整执行。研究创新须查新，业务收益须试点验证。

## 发布素材与演示脚本

封面一句话：**用已有数据，找到值得做的方向。** 副标题：**论文选题 / 业务机会 / 证据审核 / 你来选择**。

建议录制60–90秒真实操作视频：展示输入材料清单 → 同页选模式并确认权重 → 读取CSV和说明 → 展示审核发现 → 展示三个候选的证据与未知 → 调权 → 用户回复选方案。全程标注“合成样例”；等待过程可剪辑但不能包装为固定耗时保证。分别拍学术与企业短片，共用一个技能入口。

GitHub私有下载链接不能作为面向所有人的公共安装入口。公开上架时需要作者明确授权提交技能包，并使用平台生成的页面/下载地址；这不自动要求GitHub仓库公开。注册后再写可核验安装命令，当前不填占位命令。

面向电脑端数据工作流；推荐在具备文件读取及执行能力的桌面宿主使用，手机端不作为支持目标。
