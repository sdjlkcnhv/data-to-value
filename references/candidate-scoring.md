# 候选评分、可视化与用户选择

用于本轮需要比较多个数据驱动想法的任务。评分是透明的决策辅助，不是对录用、收益或成功概率的预测；默认权重与锚点是可调整的工作约定，不是经过实证校准的通用标准。

## 想法生成前的偏好设置

本轮要生成并比较多个候选时，第一步在同一个页面、原生表单或对话中一次确认学术版/企业版和对应权重；确认前不读取项目数据。初始权重使用下文两版配置；解释维度含义，允许调整或直接确认初始配置，期限、预算、可用资源作为可选的独立约束。尚无候选时不展示得分、排名或收益估算。

已有明确权重、对初始配置的接受，或“由你设置权重”的授权时直接记录，不再要求页面确认。没有这些信息时，等用户提交偏好后再生成候选；确认前只展示设置，不读取项目数据。记录模式、维度ID、权重、约束、确认来源与状态。用户只表达“更重视创新”等倾向时，可转换成待确认权重供查看，不将模型推测的数字写成用户已经选择。

偏好用于指引有依据的机会搜索与统一排序，不代替数据审核或查新；不能按偏好修改分项事实、评分锚点、未知状态或候选成熟度。保留实质差异，说明取舍，不只寻找迎合高权重维度的同类方案。低权重不免除必要的数据、评价与行动条件检查。后续比较页读取这份已确认偏好，调权只重算排序；若用户要求寻找新方向，则在原授权范围内另做候选搜索。

使用 `scripts/configure_preferences.py` 生成两版共用的设置页。模型负责运行，不让用户安装工具、复制JSON或执行命令：

```text
python scripts/configure_preferences.py --output <偏好设置.html>
```

不传 `--mode` 时不预选版本，用户在同页选择并调权；只有用户已明确选择时才传 `--mode academic` 或 `--mode business`。偏好页同样必须生成在会话工作区内，并用平台的文件交付工具声明为交付物，否则用户看不到入口。按下文“自动生成与展示”的能力选择方式预览；平台原生交互能返回输入时，直接读取明确提交的权重。

网页预览宿主（浏览器版宿主、沙箱iframe预览）里，页面没有同源权限，剪贴板接口不保证可用，页面也无法访问本机回环地址：这类环境**用对话或原生输入工具**收取偏好，把页面当作可查看的参考；页面上的“复制偏好”失败时会自动选中文本供手动复制。只在用户本机桌面、且回环地址对用户可达时，才用以下方式自动打开并接收确认：

```text
python scripts/configure_preferences.py --output <偏好设置.html> --result <已确认偏好.json> --open
```

`--result` 仅在本机回环地址启动临时接收器，确认后保存偏好并退出，默认等待600秒（`--timeout`可调整）。用户点击“确认偏好并继续”后模型读取结果，接续数据审核和候选生成，无需复制返回。此步骤同时确认版本与偏好，不选择具体方案。已有结果文件应读取复用或另用新路径，不能覆盖旧确认。等待、未提交或超时均不视为接受初始值；超时后保留断点，可改在对话确认，不自行开始生成。`--open` 只是“请求”打开：即使脚本报告请求成功，宿主也可能拒绝启动浏览器（受限桌面或沙箱常见），此时回执不代表用户已看到页面，须保留可点击文件并说明。

云端/远程环境不将服务器的localhost链接当作用户能访问的地址；优先原生输入回传，不支持时展示权重表并在对话确认。静态HTML也可生成偏好文字供发送，但不能声称它会自动回传。缺少执行能力不要求额外安装，使用对话完成相同选择。

收到本地确认后，比较页可直接应用该文件，避免重新填回默认权重：

```text
python scripts/render_candidate_scores.py --input <评分.json> --preferences-file <已确认偏好.json> --output <方案比较.html>
```

脚本拒绝未确认、模式不符或维度不一致的偏好；只替换权重和权重说明，保留候选的分项评分与证据。偏好文件须真实来自用户明确提交，不能由模型将预填配置标成已确认。仅审计、写作、既定单方案或续作已有偏好时，不强加新一轮设置。

## 1．先明确比较范围，再精选三个

先对有依据的候选去重并检查数据审核结论、关键约束及成熟度，简述入选和未入选原因。默认详细展示三个实质不同的方案；合格候选不足三个时说明原因并展示现有方案，用户要求其他数量时按其要求。不用更换模型名称凑方案，也不为满足数量保留已证实不成立的方向。

明确本次比较是“优先验证”还是“优先实施”。机会发现通常比较下一步值得验证什么；先按用户已给目标、期限、预算和资源确定共同尺度，缺失的条件可作明确假设，只有会改变选择的关键问题才询问。不同成熟度可以并列展示，但须说明哪些仅待补证据、哪些已可验证；未达到实施条件的方案不参加实施优先级的正式排名。

已证实的关键错误、不可满足的约束或未解决的数据基础冲突列为阻断项，不由总分抵消。仅缺少可补的证据可以条件性展示；让用户看到“值得继续了解”和“已经可执行”的差别。

## 2．评分尺度、证据与未知

各维度使用整数1–5分，统一为越高越有利。下列1、3、5分是锚点，2、4分表示相邻情况。先按同一任务条件定义判断口径，再评各候选；不要按本组三个方案的相对最好/最差直接赋5/1分，也不要为偏好的方案倒调权重。

每项保留：`分数或未知｜理由｜证据定位｜依据类型`。依据类型使用“已核验事实、文献依据、估算、假设、未知”；评分本身仍是判断，不能因为引用数据就称为实测分数。成熟度单独标注，不再乘一个主观“信心系数”。

未知不能填0、默认3分或靠模型猜测。尚未查新时创新度未知，缺少资源和接入依据时成本/时间未知；若能给出有依据的估算，标明假设与区间。关键未知妨碍比较时优先展示补证据任务，不强排第一。

## 3．学术版维度与初始权重

| 维度 | 权重 | 1分锚点 | 3分锚点 | 5分锚点 |
|---|---:|---|---|---|
| 创新度 | 30% | 与已核验近邻工作基本重复，新增量很小 | 有明确但范围有限的新增问题、测量、设计或方法 | 相对已核验近邻有实质新增量，能回答此前未充分解决的重要问题 |
| 研究意义 | 25% | 问题意义局限，结果很少改变领域认识 | 能澄清明确领域问题，影响范围有限 | 可显著改变重要问题的理解或实践，理由与相关工作充分 |
| 数据适配 | 20% | 关键测量、覆盖或独立单元明显不足，但仍有有限研究用途 | 核心问题可研究，存在可说明或补齐的缺口 | 关键变量、覆盖与独立单元匹配目标，来源和语义可靠 |
| 实施可行性 | 15% | 在当前资源内可推进但依赖多、投入重、排期紧 | 主要资源可得，有可控的工程或分析工作 | 数据、能力、算力与排期匹配，关键依赖少 |
| 验证设计 | 10% | 可检验范围窄，较难排除主要替代解释 | 有合适基线与评价，部分确认条件待补 | 有与主张相称的对照、确认方式及不确定性评价 |

研究意义评价问题的重要性，创新度评价相对已有工作的新增量；数据适配评价测量与覆盖，验证设计评价论证方式，避免重复计分。无有效识别或数据存在关键冲突时应处理阻断项，不以低分代替硬伤处理。课程或复现任务按用户目标调整维度，不额外要求论文原创性。

## 4．企业版维度与初始权重

| 维度 | 权重 | 1分锚点 | 3分锚点 | 5分锚点 |
|---|---:|---|---|---|
| 潜在净价值 | 30% | 有价值来源，但计入执行成本后空间有限 | 在有依据的假设下有可观改善空间 | 在相关范围的情景下价值空间大，关键采用和增量假设有依据 |
| 见效时间 | 20% | 接近任务期限，依赖长周期准备 | 在约定时间内可得到所需结果 | 可较早得到所需结果，关键时间依赖已核实 |
| 执行成本 | 20% | 接近可用预算，接入或持续投入较重 | 投入可承受，部分成本待细化 | 启动及持续投入较低，可复用资源有依据 |
| 落地条件 | 15% | 行动渠道或责任虽存在，但协作阻力较大 | 主要渠道和责任清楚，仍需有限配合 | 使用者、执行责任、行动渠道和运维接管条件明确 |
| 效果可测量性 | 15% | 能测部分结果，但增量判断或归因较弱 | 有基线、结果记录与可行评价方案 | 可获得与主张匹配的对照和完整效果记录，关键混杂可处理 |

见效时间按本轮决策定义：优先验证时比较获得可用验证结果的时间，优先实施时比较共同约定的上线或价值兑现里程碑；不得一项用原型完成、另一项用收益兑现。时间同时列工作量与日历周期。成本在相同周期、试点规模和币种下列启动投入、接入/标注、人力、动作及运维支出，明确估算区间与依据。

时间越短、成本越低，对应得分越高。期限、预算与业务量级未知时不得编造统一的天数或金额阈值。潜在净价值反映计入成本后的改善空间，成本维度反映投入承受能力；若本任务已在价值中充分评价资金约束，可统一调整权重以避免重复惩罚成本。

## 5．综合分与取舍

初始权重合计100%；生成前已确认的权重作为本轮比较起点，不在评分时重置。各候选使用相同维度、锚点与权重；维度不适用时统一移除并重新归一化，不能只给某方案删掉弱项。调整比较范围或权重后同步全部候选与图表，并记录变化。

```text
综合分 = Σ（维度权重 × 维度分数）/ Σ维度权重
```

综合分按1–5分显示，至多一位小数。存在任一未知维度时不输出完整综合分，也不将已知项重新加权冒充可比总分；显示“待补证据”及已知分项。阻断方案不参与正式排名；条件性方案即使可算总分也须标为条件性参考。按显示精度并列的方案保留并列，不利用隐藏小数强分胜负。

解释各方案的优势、最大风险、关键假设、时间/成本及最便宜的下一步。对接近的方案，检查用户可能采用的另一组合理权重或关键估算情景；若顺序变化，说明选择取决于偏好或待核条件。权重调整只改变偏好，不改变数据事实、维度原始评分或成熟度。不能将综合分换算成录用率、收益保证或成功概率。

## 6．可视化交付

使用同一份评分数据生成：

1. 评分矩阵：三个方案为列或行，展示维度、权重、1–5分及证据状态，未知单独显示。
2. 条形比较：统一1–5分含义，条形从0起、上限5；有总分时显示总分，条件性参考和阻断/未知明确标记。
3. 方案卡：观察依据、成熟度、优势与风险、时间/成本及下一步；给出建议但不代选。

环境支持交互时允许调整权重并查看综合分变化、展开证据。默认不使用雷达图面积判断优劣；若用户要求雷达图，仍附同尺度分项数值，未知轴不补0。存在未知维度或方案被阻断时不绘制条形长度，改为明确的文字标记（该方案条形整体隐藏），不得把未知当作0分参与长度比较。图表不能只靠颜色区分状态。

### 自动生成与展示

学术版与企业版均在比较步骤主动展示页面。由执行技能的模型整理有依据的评分JSON，调用随附的 `scripts/render_candidate_scores.py` 生成无需联网的交互HTML，再打开或预览；用户只需查看、调整偏好并选择方案，不承担复制JSON、执行脚本或另行下载评分工具的工作。脚本只展示已填写的评分，不推断或补写分数。

生成位置决定用户能否打开：**HTML必须生成在会话工作区内**（项目目录或平台可交付目录），并使用平台的文件交付工具声明为交付物。平台预览通常只读取会话工作区内的文件，生成到工作区之外的路径用户看不到入口；不调用交付工具时，页面虽然存在，用户也不会收到可点击的入口。

按实际运行环境选择展示方式，不根据模型品牌推断能力：

| 环境能力 | 执行动作 |
|---|---|
| 平台可预览交互HTML／制品 | 生成到会话工作区后用交付工具声明，请用户在侧边栏或预览面板打开；不再重复打开外部浏览器 |
| 本地桌面可执行Python且能打开用户浏览器 | 生成时加 `--open`，请求默认浏览器打开报告；仅作补充，不能替代交付入口 |
| 云端／远程／网页宿主或没有图形桌面 | 生成到会话工作区后用交付工具声明，经平台预览或附件交付；不尝试打开服务器上的浏览器 |
| 无代码执行或交互展示能力 | 使用环境已有展示能力；仍受限时直接给评分表与文字条形，例如 `4/5 ████░`、`未知 —`，并在对话中完成方案选择 |

网页宿主的预览通常把HTML放在受限的沙箱iframe里：脚本可以运行，滑块、评分矩阵和图表都可用，但页面**没有**同源权限，`navigator.clipboard` 一类接口不可用，页面也无法访问本机回环地址。因此在这类环境里：方案选择的“复制选择”可能失败，脚本已提供选中只读文本的兜底，用户手动复制即可；偏好确认不适合走 `--result` 回环接收器，改用对话或原生输入工具。不要承诺页面会自动把选择回传。

这些展示动作属于已请求的方案比较，无需另问用户是否打开；用户要求只看文字或不打开时遵循其偏好。已有同版本页面时复用，避免续作或重复调用不断弹窗。平台权限限制仍须遵守；不能用技能说明承诺所有聊天客户端均可自动弹窗，不为展示自动安装依赖、部署网站或上传材料。

脚本调用由模型执行（路径相对技能目录，输入与输出放项目或平台可交付的目录）：

```text
python scripts/render_candidate_scores.py --input <评分.json> --output <方案比较.html>
```

本地桌面自动打开使用同一命令并加 `--open`。脚本先完成输入校验和文件保存，再请求浏览器打开；打开失败仍保留HTML供预览或点击，不影响评分报告交付。收到打开请求的回执不代表用户已看到页面，也不代表已作选择；如缺少展示确认，说明已请求打开并保留可点击文件作为入口，不反复重试弹窗。云端路径不能直接作为用户本机可打开的链接，应使用平台的文件交付机制。

JSON字段：

| 字段 | 内容 |
|---|---|
| `title`, `mode`, `decision`, `weight_basis` | 标题；`academic`或`business`；优先验证/优先实施等共同决策范围；权重依据 |
| `dimensions` | 数组，每项含稳定`id`、`label`和非负`weight`（总和大于0）；脚本统一归一化 |
| `candidates` | 已精选方案数组，通常三个；每项含唯一`id`、`name`、`maturity`、`eligibility`、`summary`、`data_basis`、`risks`、`time`、`cost`、`next_step`、`scores` |
| `eligibility` | `ready`可比较、`conditional`条件性参考、`blocked`暂不参与；依据本轮决策范围判断 |
| `scores` | 以维度`id`为键，每项含`value`（整数1–5或`null`）、`reason`、`evidence`、`basis`；后者为已核验事实/文献依据/估算/假设/未知 |
| `recommendation` | 可选；建议及理由，不作为用户选择记录 |

评分JSON还须满足：每个候选的 `scores` 键集必须与 `dimensions` 的 `id` 完全一致；`basis` 为“未知”时 `value` 必须为 `null`，其他依据类型必须给出1–5整数。脚本会拒收不满足这些条件的输入。

`dimensions` 对本轮全部候选统一生效，不支持只给某个候选删掉弱项。确有一项维度对整轮比较都不适用时，从 `dimensions` 中移除该维度，同时从**每个**候选的 `scores` 中移除同一键，并同步偏好文件的 `weights` 键集；脚本按剩余维度重新归一化。

偏好文件（`--preferences-file`）字段：

| 字段 | 要求 |
|---|---|
| `schema_version` | 必须为 `1` |
| `mode` | 必须与本轮报告一致（`academic`或`business`） |
| `weights` | 键集必须与报告的维度`id`完全一致；值为非负数且总和大于0 |
| `confirmed` | 必须为 `true`；由偏好页确认产生的文件自带此项，模型不得把预填配置标成已确认 |
| `constraints` | 可选文本，至多4000字符 |

用 `--result` 由偏好页确认生成的JSON可直接传入；手工编写的文件也必须满足上表，否则脚本报错退出。

未知项也要填原因和待补证据；不要将秘密或无关个人信息写入报告。脚本不替代数据审核或检查用户是否已选择方案。检查报告计算、标签和可见内容后再交付。

脚本退出码：`0` 成功；`2` 参数、输入或环境错误。偏好页等待确认另有 `3`，表示超时未收到确认，属于正常暂停，应按“保留断点、改在对话确认”处理，不得记为失败或当作接受初始权重。

## 7．等待用户最终选择

展示比较后询问用户希望选择哪一方案；可建议某项，但同时列出其他方案的适用条件。允许选择具体方案、先补证据、调整权重、暂不选择；不得因排名第一自动确定主线。输入工具预选、浏览页面、调整权重或未回复均不是确认。

HTML里的方案选择仅生成待发送的回复文字；最终以用户在对话中提交的明确选择为准。未收到选择前可补齐与方案选择无关的核验、评分依据及图表修复，不启动某候选的后续实验、开发或业务试点。用户已选方案后记录方案ID、比较版本和选择范围，沿用已有选择，不重复确认；选择本身不授权额外采购、外部发布或生产变更。

权重允许为0，但至少一项大于0；零权重仅不计入加权和，不移除该项证据检查，未知项仍显示未知且不输出完整总分。

## 更便利的提交方式

本机桌面环境已确认可访问同一本机回环地址时，优先使用 `--result ... --open`，由助手启动并保持等待，页面一次确认写入回执，助手收到成功结果后读取文件继续。它连接的是当前任务的本地文件，不是调用模型API，不需要用户提供API Key。运行中定期等待结果；超时回到对话，不追认默认值。

直接打开随包start.html属于未连接的预览，不会自动建立接收器或唤醒模型。页面明确显示“离线页面”，提供复制和保存设置文件；下载后的JSON只有在用户交给当前任务并核验版本/维度后才使用，不能自动加载下载目录里的旧确认。平台若有原生可回传表单，优先使用，不强制HTML。

页面中的快捷配置仅填入草稿，用户仍须点击确认。切换版本保留各自本次页面草稿，不将数据存到外部服务。自动提交请求等待10秒后可恢复操作或使用备选方式；成功以接收器回执为准，不以浏览器打开或请求发出为准。
