针对0.2.0。把导入、执行、展示、确认四项分别验收；“模型能理解说明”不能代替宿主提供文件、执行或交互能力。初始化回执中的ready只表示该配置的依赖与列出的样例通过，不代表所有真实文件、所有格式变体或整个平台流程通过。

## 格式验收

安装探测会为本机生成逐格式结果，不借用其他电脑的回执。本地测试环境：Windows、Python 3.10.11；common专用环境的pandas 2.3.3、NumPy 2.2.6、openpyxl 3.1.5、calamine 0.8.2、pyarrow 24.0.0、pypdf 6.19.0、python-docx 1.2.0。

| 格式或功能 | 本次测试证据 |
|---|---|
| CSV/TSV、JSON/JSONL/NDJSON、TXT/MD/LOG | 合成样例的内容读取；另测CSV重复列、引号换行、抽样、中文编码失败/显式读取、JSON重复键 |
| SQLite三种后缀、ZIP清单 | 合成样例；SQLite表名转义、二进制值；源文件哈希不变 |
| XLSX、ODS、Parquet、Feather | 合成样例的实际字段/值读取；XLSX额外检查公式保留及表数量截断 |
| DOCX、文本PDF、HTML/HTM、XML | 合成样例文字提取；另测加密/空白PDF和XML实体拒绝 |
| XLS、XLSB、XLSM | 已配读取器；初始探测没有这些格式的专用样例，不标记已实测 |
| 图片／扫描PDF OCR | 独立安装配置和入口；需外部Tesseract及目标语言数据；本次没有引擎，不标记已验证 |
| 未知格式、损坏文件、缺库、超过大小限制 | 返回明确失败或未读状态；不安装依赖、不填造内容 |
| 两版偏好页、评分页 | 文件生成、ASCII控制台中文路径回归、已确认权重传入；不代表目标宿主页面已渲染 |

可复现测试：`python -m unittest discover -s tests -v`（使用common配置解释器）。`scripts/runtime_probe.py common`为安装时基础样例检查；更深的格式问题由测试集和实际项目审核处理。

发布后保留具体提交的Actions记录；新增平台测试填写客户端版本、操作系统、模式选择、偏好展示/确认、真实读取和方案选择结果，不能只填“支持豆包/DeepSeek”。

## 自动化模板部署状态

`tests/compatibility-workflow.yml`提供三操作系统、两个Python版本的自动化矩阵。当前GitHub发布授权不含workflow权限，未将其作为活动工作流部署，也未宣称云端测试通过。获得工作流写入权限后，可复制到 `.github/workflows/compatibility.yml` 并查看该提交的Actions结果。模板文件本身不触发CI。
