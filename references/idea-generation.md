# 从数据证据生成值得比较的方案

用于机会发现、学术选题和用户要求重新寻找方向。承接已确认的版本、权重及数据审核，输出可比较的候选；不重新弹出设置页。只审计、实现既定方案或润色时不加载本文件。

## 1．提炼机会线索，不从模型清单起步

复用审核结果，提取会改变问题选择的观察能力或事实，放进现有项目记录即可。每条线索保留：

| 项目 | 最少记录什么 |
|---|---|
| 证据 | 文件/表/字段或文档位置、已读范围、相关核验结果；可用 E1 等短编号引用 |
| 观察能力或现象 | 数据能够区分/连接/追踪什么；已经测得的现象另列，不把“能观察”写成“已发生” |
| 边界 | 实体、时间、覆盖、可用时点及关键未知；只读样本就不推断全体规模 |
| 问题线索 | 哪个研究解释、业务动作或信息缺口可能因此得到检验或改善 |

不是每个字段都要变成线索。优先选择能区分现有解释、揭示现状不足，或支持新动作的信息。说明不足时可依据已核验的观察能力提出条件性机会；不能虚构趋势、用户痛点或企业当前流程。

分别记录可由材料确认的背景、用户陈述及尚待确认的假设。只追问会改变方向的缺项，例如研究对象、当前做法、谁能执行动作；用户无从补充时保留条件，不反复追问。

## 2．从不同问题角度发散

围绕有依据的线索，从适用的不同角度搜索候选。以下是启发入口，不是每项必做的清单：

| 数据能提供什么 | 学术版可问什么 | 企业版可问什么 |
|---|---|---|
| 过去混在一起的群体或场景 | 现有结论在什么条件下成立或失效？ | 哪些对象需要不同服务或资源配置？ |
| 多源记录或重复测量 | 原有测量是否偏误，能否区分竞争解释？ | 哪些信息连接后能改变核对、服务或决策？ |
| 过程、顺序或变化 | 哪种解释预言不同的时间模式？现有设计能否区分？ | 何时采取什么动作可能减少等待、损失或错配？ |
| 失败样本或现行规则的边界 | 失效来自数据、目标、测量还是方法假设？ | 哪些环节适合规则修正、人工协同或流程调整？ |
| 持续记录但尚未利用的信息 | 能否建立可复查的测量、数据证据或评价任务？ | 能否形成有人需要的新服务或数据产品？ |

有多种观察能力时，不因最先想到预测任务就停止搜索；只有一种能力时不强凑多路线。权重引导侧重，但低权重维度对应的机会仍可能有价值。新颖的机会允许保留，前提是说清数据依据和可负担的补证据路径。

学术版先写研究问题与可能改变的认识，再决定是否需要新方法。企业版先写谁在什么时候改变什么动作，再决定是否需要模型。数据清洗、建模和上线通常是同一方案的步骤，不作为三个互斥候选；同一问题换三种算法也不是三个想法。

对每个初步方向，用一句话说明“若没有这份数据的某项观察能力，这个方向会失去什么依据”。如果把数据集名称替换后原文仍可套用，补上具体证据与边界；这项检查要求具体，不要求数据独有，也不否定复现研究。

## 3．把线索变成可以反驳的机会

候选的核心是一条短的公开论证，不要求展示内部推理过程：

```text
已核验事实/能力 → 值得解决的问题 → 拟议解释或动作
→ 相比现状的新增价值 → 最可能使方案失败的条件 → 最便宜的区分办法
```

学术候选说明：研究单元和范围；待检验的主张；最强的合理替代解释；什么可观察结果能区分二者。若现有数据不能区分，只能标为探索性关联或待补证据的研究设计。探索中发现的模式要继承探索身份，不按“看起来新奇”挑显著子群。

企业候选说明：使用者；决策时点；可执行动作；预期改变的业务结果；现状基线和采取动作的代价。只有结果预测而无行动路径时，可以保留预测工具的条件性机会，但不能推导业务收益。现状未知就写待核，不假设企业原来全靠人工。

每个候选挑出**一个最影响去留的未知**，并写检查结果的分支：若成立如何继续，若不成立是改范围、暂缓还是淘汰。早期不强填ROI或统计阈值；有决策依据时才给数值门槛。区分“方案本身无价值”和“目前无法判断”。

## 4．用已有工作修订候选，而非事后装饰

在详细评分前，围绕拟保留方向检查最近相关研究、现有流程和可用替代办法；按学术/企业细则记录实际阅读和核验程度。查新与生成允许迭代：发现已被覆盖就修改问题或合并方向，发现关键条件不成立就收缩或淘汰，不能只在原题目后补几条引用。

比较的是能回答同一问题、达成同一动作的最强合理替代，而不只选容易打败的基线。学术新增量可在问题、测量、识别、数据证据或方法上；企业新增量可在现有信息的新用途、可执行动作或成本改善上。简单办法已足够时仍可成为好企业方案。

无法联网或没有企业流程资料时，明确相应边界；不能声称“首次”“现有方法都无法解决”或给查新不足的创新度打分。针对具体关键未知继续核验，不以无边界检索拖延交付。

## 5．去重、检查依赖，再选比较对象

先比较全部有依据的初步方向，按问题/解释/动作而非题目名称去重。记录保留、合并、暂缓、淘汰的关键理由；可只保留简表，无需把每个草案扩成长报告。

识别候选关系：

- **替代**：竞争同一预算或回答同一决策，可直接比较。
- **互补**：可以并行，但不能因各自得分高就自动合并投入。
- **前置依赖**：例如先补采标签才能做效果检验，应放入对应方案的准备工作。

先排除已证实且无法在约束内修正的阻断项；条件未知、但能低成本补证据的候选保留条件性状态。不要将“资料最齐全”自动等同“价值最大”。

按 [评分细则](candidate-scoring.md) 定义共同决策范围，再精选通常三个实质不同的候选；不必固定生成多少初稿。候选不足就如实交付，不为多样性保留无依据方向，也不刻意安排一个差方案衬托推荐项。用户只要单一既定方向时不强加发散。

只有在证据与同口径成本可比时，才判断某候选各方面均不优于另一候选；含关键未知时不能认定被全面超越。对分数接近或未知很多的方案，以最值得先补的证据说明取舍，不强排第一。

## 6．交付可选择的方案卡

使用 [候选卡](problem-validation.md#候选卡) 和 [首次交付](first-delivery.md)，每个候选有稳定ID。标题直接写问题或动作，例如“按工单类型调整复核顺序”，不使用尚未证明的“高收益智能平台”。

一张卡至少让用户看懂：做什么；为什么这份数据支持提出它；相对现状可能增加什么；最大未知；最简单验证及失败分支。早期实现只写可行路径，不提前编造架构、结果或收益。

到达交付出口时应满足：

- 所有候选能追溯到已核验的事实或观察能力，推测与实测分开。
- 各候选的问题、解释或动作有实质差别，前置任务没有伪装成独立方向。
- 每项都有价值来源、合理替代及决定去留的检查；无法完成的部分标明影响。
- 有共同的比较范围，评分沿用已确认权重，最终方案仍由用户选择。

本轮发现阶段可以完成已授权、低成本、只读的证据核验；候选的正式实验、开发或业务动作仍需遵循主文件的用户选择与授权边界。授权预算用尽，或剩余关键未知只能通过新的采集/试验解决时，交付当前候选与限制，不无止境换模型或凑数量。
