# 从问题到低成本验证与交付

用于生成想法、方案审查、选择验证顺序和工程拆分。记录足以改变判断的信息，不预设项目必须使用机器学习。

## 从观察能力生成候选

先从已核验的结构、语义和事实说明数据能观察什么，再结合领域知识、既有研究或业务流程提出问题。所依赖字段或文件须已有适用于该用途的审核结论；说明与数据的关键冲突未解决时，可提出核验或修复任务，不将可疑差异作为已成立的发现。数据具备观察能力，不代表某种差异或机制已经存在；尚未测量的现象须写成待检验假设。

需要发现并比较多个候选时，按主文件约定先确认用户偏好，再开展候选生成。用权重和约束决定搜索侧重，仍需保留有依据的实质差异；不能为匹配偏好编造线索或调整事实。偏好确认和最终选定方案分别记录。

按数据与目标选择有用的启发路径，不逐项凑候选：

| 数据提供的观察能力 | 学术问题入口 | 企业机会入口 |
|---|---|---|
| 能区分过去混在一起的群体、情境或状态 | 既有结论是否有适用边界或异质性？ | 是否需要不同服务、规则或资源配置？ |
| 能连接过去分散的记录或测量 | 能否改善测量，或检验新的关系？ | 能否减少核对、等待、重复工作，或支持新服务？ |
| 能观察变化前后的过程与相关对照 | 能否区分竞争解释，形成可检验机制或识别设计？ | 能否改善介入时机或操作流程？ |
| 能定位现有做法反复失败的条件 | 是否存在可解释、可推广的失效机制？ | 是否有低成本纠错、人工协同或资源调配机会？ |

为有依据的线索提出可能解释或用途，同时给一个关键替代解释或失败条件，再写候选卡。前后变化本身不构成因果识别，群体差异也不自动证明差异化服务有效。

候选应在研究问题、解释机制、业务动作或服务对象上存在实质差异；仅替换模型、损失函数或技术名称通常合并为同一候选的实现变体。不同技术若确实改变了可回答的问题或可执行的动作，应明确说明。

## 候选成熟度

成熟度表示当前证据支持到哪一步，与预期价值分开判断：

| 成熟度 | 最低依据与可作判断 | 下一步 |
|---|---|---|
| 机会假设 | 已核验的观察能力或事实提供线索，价值来源可解释；关键标签、对照或行动条件可未知 | 明确关键未知、最低成本补证据路径，以及什么发现会淘汰该候选 |
| 可验证方案 | 对拟验证的具体主张，有明确问题、可行输入、评价办法及可执行的最小验证 | 在授权范围内开展验证；方案可测不等于已有效 |
| 已获支持方案 | 已完成的结果支持明确主张，比较、适用范围和限制可追溯 | 决定是否扩大验证或实施；离线有效不等于已部署或已产生收益 |

缺少标签、对照或行动记录时，说明影响以及可行的补证据办法，如核验元信息、小范围标注或补记行动与结果；记录成本和依赖，未授权的采集或业务动作只作为建议。补证据路径值得尝试时可保留条件性候选，不把缺口填成已知。若已证实核心假设不成立，或在本任务约束内没有可行验证路径，则修正、暂缓或淘汰并说明原因。

成熟度按具体主张判断，证据变化后可以下调；某个前置条件通过，不自动使整个方案成为“已获支持”。没有可读取数据时仍按主文件约定只交付条件性框架，不把材料描述升级为核验事实。

## 候选卡

每个候选按成熟度填写已知内容、关键未知和下一步；可合并成短表。机会发现阶段给足以判断是否值得补证据的信息，不强填尚无依据的标签、数值门槛或实现细节：

| 内容 | 要回答的问题 |
|---|---|
| 数据事实 | 哪个核验结果引出问题或机会？具体数据、字段、时间与群体是什么？发现了什么尚未利用的信息？ |
| 问题与价值 | 谁需要答案？哪项认识、流程或决策有机会改善，或可形成什么新服务？ |
| 任务 | 分析/预测/检测/排序/估计效果/优化什么；输入、输出、标签、使用时点是什么？ |
| 基线与新增量 | 现有流程或最简单模型为何不足？新增量来自测量、问题、识别、算法还是工程？ |
| 成熟度与缺口 | 属于哪一成熟度？哪项关键条件未知，如何以最低合理成本补证据？ |
| 证据角色 | 哪些数据用于开发、校准、独立验证、压力测试或解释？ |
| 验证 | 什么观察会支持或否定主张？主要指标、分母和可接受损伤是什么？ |
| 成本与降级 | 最小实现、预算、依赖、失败后的替代或停止结果是什么？ |

使用者没有预定问题或业务方案时，先依据数据形成候选，不把“请先告诉我你的想法或ROI目标”作为启动门槛。候选仍须连接领域知识、可能的使用者与可观察结果，不能只罗列相关性或模型名称。

在已授权的机会发现范围内，可淘汰候选并继续搜索，记录原因。需要改变用户已确认的主要目标、已选主线或交付类型，或显著扩大投入与授权范围时，说明障碍、可保留的目标和调整代价，先讨论再推进；用户未回应不是同意转向。同目标内的证据检查和实现修正可以继续，不反复追问已经无法补齐的材料。

## 定义对象后才选择模型

把决策写成“在时刻 t，针对单元 u，利用信息 I(t)，输出 O，依据之后可核验结果 Y 评价”。非时间任务也要明确信息边界和对象。

以下差异会改变方案：

- 单次观测、正常均值、正常中位数、未来预测分布、潜在反事实是不同对象。
- 预测未来结果、估计一个策略的效果、建议最优动作是不同任务。高风险客户不等于最容易被干预改变的客户。
- 节点/客户均值改善不保证局部改善；总量与人均、订单与订单行、事件与窗口不可混用。
- 架构能接入新数据、参数可迁移、未经适配泛化是三种不同主张。

需要比较或实现模型时，模型表列输入、操作、输出、学习对象、需要的数据和工程角色。只有需要实现 ML 时写真实维度、掩码、损失和训练范式；未知维度写计算规则和何时核定，不编常数。

## 先查硬伤，再排序

按成熟度审查。机会假设先判断事实依据、价值来源，以及关键未知是否值得且能够补证据；可验证方案再核查可用输入、评价目标、合法的信息时点及适用的基本对照。已证实的定义错误、泄漏或不可行约束先处理，不以“创新5分”抵消。尚未获得标签或对照不自动等于方向无效，也不能据此宣称已可验证。

有多个候选需要筛选时，执行主文件所链接的候选评分细则：默认精选三个实质不同的方案，使用按版本区分的1–5分锚点、透明权重与证据说明，并可视化比较；不足三个不补造。精选前先对全部有依据的候选作足以判断去留的比较，记录入选/未入选原因，不只给最先想到的三个评分。

技术能做、能成为好论文、能带来业务净收益分开评估。成熟度不同的候选须注明差别；明确本轮是在比较验证优先级还是实施优先级，不能混淆。没有现成收益方案不扣分，缺乏价值来源依据标为待核。评分帮助用户理解取舍，最终由用户选定方案；未选择前不把最高分当作新主线或启动后续实验与开发。

## 最小验证协议

仅在本轮包含验证设计或执行时展开。验证前写清待解决的关键问题、所需证据、预算与去留门槛。早期机会可以先做字段语义核验、小范围标注可行性检查或动作条件核验；这些检查不强制训练模型。需要评估效果时，再明确假设、样本与切分、主要指标、基线和成功/失败/停止条件。预算可用人日、算力、存储、查询成本或人工处理能力表达；先解决会改变决策的高影响不确定性。

顺序通常是：数据/规则可用性 → 简单基线 → 少量有效反例 → 新增组件 → 扩大验证。已做检查无需无理由重复。可行性门槛只是项目去留标准，不能称为统计保证。

对时间数据用向前切分，重复实体/同源副本按相应单元隔离。训练、选择、校准、评价角色分清；在线适应可读取已自然到达的结果，超参数和更新策略不得看尚未到达的目标结果。已有开发数据可继续探索，不能追认为盲测。

对照至少覆盖能解释主张的最近替代：现有流程、简单规则/持久性/线性/树，以及相关已有方法。方法数量不固定；同输入、标签、预测提前量、支持集和成本比较。不允许给新组件更多有效信息却把差异全算为架构贡献。

## 退化规则与评测反例

按具体风险选择少量反例：

- 规则是否存在合理输入可以通过？阈值和区间是否使它永远不输出？
- 不预测、不告警、不行动是否被算作“零错误成功”？同时报告覆盖/工作量/漏检和条件风险；分母为零记不适用。
- 已观察到的未发生、一直未完成、观测截断、缺测和统计拒判是否区分？未知不能填成失败，也不能填成成功。
- 缺测被平均或最大值忽略后，是否仍声称完整总体覆盖？汇总是否抵消了局部问题？
- 评分器是否漏记最重要的错误，例如真值永不恢复却宣布恢复，或金额重复计入收益？
- 人工扰动是否只有新方法擅长的机制？合成真值用于机制验证，不冒充新增真实事件。

区间类方法须说明覆盖对象、覆盖概率的假设以及点、日期块、全路径和条件风险的差别。不能把样本不足下某个算法的特定最低样本要求当作所有研究的普遍限制。

## 验证结论与停止

按证据给四类决定：继续（进入下一个明确门槛）；修正（定位到具体错误）；收缩（保留可支持的目标）；停止该路径（关键主张无增量或不可检验）。不要因一次原型失败推断未实现方法必然失败，也不要用“也许更大模型有用”无限延期。

显著性分析使用与数据生成和决策相符的独立单元；报告效应大小、不确定性和业务/领域意义。重叠滑窗、节点数、随机种子及人工情景不是独立事件。无足够独立样本时报告案例或开发证据，而非虚假的总体泛化保证。

## 工程交付

每条 issue 必备：

```text
标题 / 目标
输入：具体文件、字段、快照或上游输出
实现：键、过滤、转换与时间边界；建模时加张量/损失/训练方式
输出：可定位的表、脚本、模型、图或报告
依赖：先后关系及已有可复用产物
验收：一句话可由工程师或检查程序判断
资源：估算及其依据，区分开发工时与运行时间
失败处理：替代口径、降级输出或停止条件
```

好验收如“输出各源解析行列数、重复实体-时间键数、缺失比例与说明冲突表”，或“所有预测的训练/更新标签可用时刻不晚于发布时间，且早先预测不可覆盖”。“准确率高”“工程可用”“生成精美图表”无法直接验收。

保留一份与本轮范围相称的最小项目记录：使用者已选版本与本轮交付、输入身份及读取范围、已确认偏好及调整、候选成熟度与关键未知、选择及淘汰原因；涉及实验、写作或工程时再补配置/结果、主张-证据映射或issue。可放同一文件或已有系统，不强制新建所有目录。数据、代码和文稿引用同一版本；收缩方向后同步已有的摘要、指标、角色和任务列表。
